# Coding Conventions

**Analysis Date:** 2026-08-12

> **Two coexisting style dialects.** This codebase contains two distinct
> conventions that must NOT be blended within a single file:
>
> 1. **shadcn/ui primitives** (`components/ui/*`) — generated/vendored code.
>    No semicolons, `function` declarations, `cva` variants, `data-slot`
>    attributes, `cn()` merging, exports grouped at bottom.
> 2. **App + custom components** (`components/common/*`, `components/landing/*`,
>    `app/*`) — hand-written. Semicolons, `import React from "react"`, named
>    `export function`, template-literal `className` strings, inline prop
>    interfaces.
>
> When editing an existing file, match that file's dialect. When creating a new
> file, use the dialect of the directory it lives in (see below).

---

## Design Source of Truth

**`docs/DESIGN_SYSTEM.md` is the AUTHORITATIVE reference for all UI and design
decisions.** Before writing or changing any UI, consult it for: brand identity,
color roles, typography scale, spacing scale (4px base), border radius, shadow
philosophy ("border first, shadow second"), layout widths (max 1280px),
component inventory, accessibility requirements, feedback states, and brand
voice. Any new visual work must trace back to a rule in that document.

**Concrete token layer:** The design-system *intent* is implemented as CSS
custom properties in `app/globals.css` under the `@theme inline { ... }` block
and `:root { ... }`. Day-to-day code consumes these tokens through Tailwind v4
utility classes (e.g. `bg-kita-green`, `text-ink`, `border-line`, `bg-paper`).
Never hardcode hex values in components — always use the token-backed utilities.

**Known divergence to reconcile deliberately:** `docs/DESIGN_SYSTEM.md`
specifies **Inter** and a Deep-Emerald palette (`#087F5B`), while the shipped
implementation in `app/globals.css` / `app/layout.tsx` uses a richer
"campus bulletin board" theme — **Bricolage Grotesque** (display),
**Plus Jakarta Sans** (body), **Space Mono** (prices/data), with `kita-green`
`#0C6B4E`, `ink` `#16241D`, `spark` `#F2B32C`, `paper` `#F4F3EA`. Treat
`docs/DESIGN_SYSTEM.md` as canonical for *principles and roles*, and
`app/globals.css` as canonical for the *concrete implemented tokens*. Do not
silently "fix" one to match the other — surface the mismatch and change both
intentionally. See the dedicated section "Design System (Source of Truth)" below.

## Naming Patterns

**Files:**
- **kebab-case** for every source file: `product-card.tsx`,
  `verification-badge.tsx`, `how-it-works-section.tsx`, `use-mobile.ts`,
  `utils.ts`.
- One primary exported component per file; file name mirrors the component
  (kebab-cased): `Navbar` → `navbar.tsx`, `ProductCard` → `product-card.tsx`.

**Directories:**
- `components/ui/` — vendored shadcn primitives.
- `components/common/` — shared, reusable app components (`logo`, `product-card`,
  `verification-badge`).
- `components/landing/` — page-section components for the marketing/home page.
- `app/` — Next.js App Router routes, layout, global CSS.
- `lib/` — framework-agnostic helpers (`lib/utils.ts`).
- `hooks/` — custom React hooks (`hooks/use-mobile.ts`).

**Components:** PascalCase (`ProductCard`, `VerificationBadge`, `CategoryTabs`).

**Functions/variables:** camelCase (`onSelectCategory`, `isLiked`, `activeLink`).

**Hooks:** camelCase, `use` prefix, kebab-case file (`useIsMobile` in
`hooks/use-mobile.ts`).

**Types/Interfaces:** PascalCase. Prop interfaces suffixed `Props`
(`ProductCardProps`, `LogoProps`, `CategoryTabsProps`). Union type aliases are
plain PascalCase (`SellerType = "Student" | "Faculty"` in
`components/common/verification-badge.tsx`).

**Module-level constants:** SCREAMING_SNAKE_CASE
(`CATEGORY_LABELS`, `CATEGORIES`, `MOBILE_BREAKPOINT`).

**cva variant maps:** `<name>Variants` exported alongside the component
(`buttonVariants`, `badgeVariants` in `components/ui/button.tsx`,
`components/ui/badge.tsx`).

## Code Style

**Formatting:**
- No dedicated formatter config detected (no `.prettierrc`, no `biome.json`).
  Formatting is enforced only implicitly. This is why the two dialects diverge.
- Indentation: 2 spaces throughout.
- Quotes: **double quotes** in both dialects.
- Semicolons: **present** in app/custom code (`components/common/*`,
  `components/landing/*`, `app/*`, `hooks/*`); **absent** in shadcn primitives
  (`components/ui/*`, `lib/utils.ts`).

**Linting:**
- ESLint flat config at `eslint.config.mjs`, extending
  `eslint-config-next/core-web-vitals` and `eslint-config-next/typescript`.
- Ignores: `.next/**`, `out/**`, `build/**`, `next-env.d.ts`.
- Run: `bun run lint` (script: `"lint": "eslint"` in `package.json`).

**TypeScript:**
- `strict: true`, `noEmit: true`, `moduleResolution: "bundler"`,
  `jsx: "react-jsx"`, `target: ES2017` (`tsconfig.json`).
- Path alias `@/*` → project root. Import app modules as
  `@/components/...`, `@/lib/utils`, `@/hooks/...`.

## Import Organization

Observed order (top to bottom), with a blank line between groups in ui
primitives:

1. Third-party / framework: `react`, `next/*`, `@base-ui/react/*`,
   `class-variance-authority`, `lucide-react`, `clsx`, `tailwind-merge`.
2. Internal aliases: `@/lib/utils`, `@/components/...`, `@/hooks/...`.
3. Relative siblings: `./verification-badge`.

**Path aliases:** Always use `@/` for internal imports; relative imports appear
only for tightly coupled siblings within the same feature folder
(e.g. `product-card.tsx` importing `./verification-badge`).

**React import:** shadcn primitives use `import * as React from "react"`;
app/custom components use `import React from "react"` (with named hooks pulled in
the same statement, e.g. `import React, { useState } from "react"`).

**No barrel files.** There are no `index.ts` re-export files; import directly
from the concrete module path.

## Component Patterns

### shadcn/ui primitives (`components/ui/*`)

- Built on **`@base-ui/react`** primitives (NOT Radix). Some use
  `useRender` + `mergeProps` (`components/ui/badge.tsx`) instead of a plain
  element.
- `style: "base-nova"`, `baseColor: "neutral"`, RSC enabled, CSS variables on
  (`components.json`). Icon library: **lucide**.
- Variants via **class-variance-authority** (`cva`) with `defaultVariants`, typed
  through `VariantProps<typeof xVariants>`.
- Class merging via **`cn()`** from `@/lib/utils` (= `twMerge(clsx(...))`).
- Each element carries a `data-slot="<name>"` attribute for styling/targeting.
- Typed with `React.ComponentProps<"tag">` (+ intersection for extra props).
- Declared as `function Component(...)`, exported grouped at file bottom:
  `export { Button, buttonVariants }`.
- Reference: `components/ui/button.tsx`, `components/ui/badge.tsx`,
  `components/ui/card.tsx`.

### App + custom components (`components/common/*`, `components/landing/*`)

- Named export at declaration: `export function ProductCard(...)`.
- Props typed by a local `interface XProps` (or `export interface` when the shape
  is reused, e.g. `ProductCardProps`, `CategoryItem`).
- Default values via destructuring defaults
  (`size = "md"`, `initialLiked = false`, `className = ""`).
- `className` composed with **template literals**, not `cn()`
  (`components/common/product-card.tsx`, `components/landing/navbar.tsx`).
  `cn()` is currently reserved for the ui primitives; prefer `cn()` for any new
  component that has conditional/merge-prone classes.
- Icons: **lucide-react** only (`Heart`, `Menu`, `ArrowRight`, `BadgeCheck`…),
  sized with Tailwind (`w-4 h-4`).
- Reference: `components/common/product-card.tsx`,
  `components/common/verification-badge.tsx`, `components/common/logo.tsx`,
  `components/landing/navbar.tsx`, `components/landing/category-tabs.tsx`.

### Server vs. Client boundary

- Server Components by default (App Router). Files add `"use client"` **only**
  when they use state/effects/handlers.
- Client examples: `navbar.tsx`, `product-card.tsx`, `category-tabs.tsx`
  (use `useState`/`onClick`).
- Server examples: `logo.tsx`, `verification-badge.tsx`, `hero-section.tsx`,
  `cta-section.tsx`, `for-sellers-section.tsx`, and the page/layout
  (`app/page.tsx`, `app/layout.tsx`).
- Keep interactivity in the smallest leaf; the home page (`app/page.tsx`) is a
  server component that composes section components.

## Design System (Source of Truth)

**Canonical reference: `docs/DESIGN_SYSTEM.md`.** Summary of the rules code must
honor (see the document for full detail):

**Color roles** (implemented as tokens in `app/globals.css`):
- Consume via Tailwind utilities backed by CSS vars. Implemented palette:
  `ink` `#16241D`, `ink-soft`, `muted` `#4F5B53`, `paper` `#F4F3EA`,
  `paper-deep` `#ECEBDD`, `surface` `#FFFFFF`, `kita-green` `#0C6B4E`
  (+`-deep`,`-soft`), `spark` `#F2B32C` (+`-deep`,`-ink`,`-soft`),
  `line` `#E3E2D4`, `line-strong`. Semantic shadcn aliases (`--primary`,
  `--secondary`, `--destructive`, `--border`, `--ring`, …) map onto these in
  `:root`. `destructive` is `#D64545`.
- Green is the primary identity; gold (`spark`) is used sparingly for featured /
  premium / achievement emphasis. Never let gold overpower green.
- **Never communicate state by color alone** — always pair with text or icon
  (see `VerificationBadge`, which combines color + `BadgeCheck` icon + label).

**Typography:**
- Fonts loaded with `next/font/google` in `app/layout.tsx`, exposed as CSS vars
  (`--font-bricolage`, `--font-jakarta`, `--font-space-mono`) and applied on
  `<html>`. Use `font-display` for headings, `font-sans` for body, `font-mono`
  for prices/data/eyebrows.
- Headings (`h1–h4`) auto-use the display face with `-0.02em` tracking (set in
  `@layer base`).

**Component-layer utilities** (defined in `@layer components` in
`app/globals.css`) — use these instead of re-implementing:
- `.eyebrow` — mono uppercase label.
- `.tabular` — mono tabular numerals for prices (used with `₱` +
  `.toLocaleString()`, see `product-card.tsx`).
- `.marker` — gold highlighter swash behind key words.
- `.shadow-flyer` / `.shadow-flyer-lg` — subtle lifted-paper card shadows
  (honors "border first, shadow second").
- `.pin` — pushpin dot signature element.
- `.bg-corkboard` — dotted atmospheric background band.
- `.scrollbar-none` — hide scrollbar on horizontal rails.

**Radius:** token scale in `@theme` (`--radius-sm 6px` … `--radius-2xl 24px`);
use `rounded-lg`/`rounded-xl`/`rounded-2xl` utilities. Moderate rounding; pill
shapes (`rounded-full`) reserved for status/category/verification/filter chips.

**Layout:** centered container `max-w-[1280px]` with responsive horizontal
padding (`px-4 sm:px-6 lg:px-8`), per `navbar.tsx`. Mobile-first.

**Motion:** subtle, 150–250ms; `kita-rise` keyframe + `.rise`/`.reveal`
scroll-reveal utilities. All motion is reduced-motion safe via
`@media (prefers-reduced-motion)` guards in `app/globals.css` — preserve these.

**Icons:** Lucide only; do not mix icon families.

**Images:** `next/image`, consistent aspect ratios (`aspect-[4/3]` in
`product-card.tsx`), always `alt` text, `sizes` for responsive loading. Remote
images restricted to `images.unsplash.com` (`next.config.ts`
`images.remotePatterns`).

## Accessibility

Treated as a first-class convention (matches `docs/DESIGN_SYSTEM.md` §27):
- Semantic landmarks: `<header>`, `<nav>`, `<main>`, `<footer>`.
- ARIA on interactive elements: `aria-label`, `aria-pressed`, `aria-current`,
  `aria-expanded` (see `navbar.tsx`, `product-card.tsx`, `category-tabs.tsx`).
- Decorative elements marked `aria-hidden="true"` (pushpins, spark dots).
- Global on-brand `:focus-visible` outline defined in `@layer base`
  (`app/globals.css`); components also add explicit `focus-visible:` classes.
- Images always have meaningful `alt` (product title used as alt).
- Reduced-motion respected globally.

## Error Handling

- **No backend / data layer yet.** The app is currently presentational
  (landing page + demo data). There are **no** `try/catch` blocks, no API error
  handling, and no form validation implemented in source.
- `docs/DESIGN_SYSTEM.md` §15 (Forms) and §19 (Feedback States) define the
  target patterns: every input needs a visible label + helper text + validation
  feedback; every important action needs Success/Error/Warning/Loading/Empty
  states, with skeleton loading preferred over spinners.
- **When adding logic:** introduce explicit error/empty/loading states per the
  design system, and colocate user-facing copy with the friendly, concise brand
  voice (`docs/DESIGN_SYSTEM.md` §31).

## Comments

- Sparse, purpose-driven. Used to explain *intent* / design metaphor rather than
  restate code (e.g. `// Pushpin — the flyer is tacked to the board`,
  `// Type is encoded in color: students in kita-green, faculty in marigold.`).
- `app/globals.css` uses a banner comment block to document the token system —
  keep that block current when tokens change.
- JSDoc is rare; one example documents a prop
  (`/** Optional Tailwind rotate class ... */` in `product-card.tsx`).
  Add JSDoc for non-obvious public props.

## Function & Module Design

- **Function components** only; no classes.
- Props destructured in the signature with inline defaults.
- Prefer small, composable, presentational components with no embedded business
  logic (`docs/DESIGN_SYSTEM.md` §34).
- Exports:
  - ui primitives → named exports grouped at file bottom, including the
    `*Variants` object.
  - app/custom → `export function` at the declaration site; `export interface`
    /`export const` for shared prop shapes and data (`CATEGORIES`).
- No default exports except Next.js route conventions
  (`app/page.tsx` → `export default function Home`,
  `app/layout.tsx` → `export default function RootLayout`).

## Adding New Code (quick rules)

- New shared component → `components/common/<kebab-name>.tsx`, app dialect.
- New page section → `components/landing/<kebab-name>.tsx` (or a future
  route-specific folder), app dialect.
- New primitive from shadcn → generated into `components/ui/`; leave its dialect
  as-is.
- New hook → `hooks/use-<name>.ts`, `use` prefix, app dialect.
- New pure helper → `lib/<name>.ts`.
- Always consume design tokens via Tailwind utilities; never hardcode hex.
- Verify any Next.js API against `node_modules/next/dist/docs/` first.
